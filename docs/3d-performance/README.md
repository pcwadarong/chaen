## 2. 남은 문제

### 🟡 F-5a. `hair_color`와 `hair_color-hair_alpha`가 둘 다 임베드되어 있다

| 이미지                  | 해상도 | KTX2  |
| ----------------------- | ------ | ----- |
| `hair_color`            | 2048²  | 378KB |
| `hair_color-hair_alpha` | 2048²  | 706KB |

알파 유무만 다른 동일 아트로 보인다. 병합하면 파일 ~378KB와 그만큼의 VRAM이 준다. 캐릭터 GLB 재변환이 필요하므로 `.v5`로 올려야 한다.

> F-5의 나머지 항목이던 `skin_normal` 해상도는 #95에서 이미 해결됐다 — 지금 1024²다.

### 🟡 F-5b. `public/thumbnail.png`가 1.77MB PNG

OG 이미지이자 e2e 픽스처의 액자 사진이다. WebP 전환 여부를 정해야 한다. OG 이미지는 크롤러 호환성 때문에 PNG/JPEG를 요구하는 곳이 있어 **단순 교체가 아니라 용도별 분리**가 필요할 수 있다.

### 🟠 N-1. 로딩 오버레이는 캐시가 못 덮는 구간을 잰다 — 그리고 ~600ms 바닥이 있다

**"캐시됐는데 왜 매번 로딩바가 뜨나"를 파고들어 나온 것이다.** HTTP 캐시는 **바이트만** 덮는다. 파싱·트랜스코드·GPU 업로드·셰이더 워밍은 페이지를 새로 열 때마다 처음부터 다시 한다.

프로덕션 웜 캐시 재방문 실측 (GPU 브라우저, dev 아님):

|                                                 | 1회차(콜드) | 2회차(웜) | 3회차(웜) |
| ----------------------------------------------- | ----------- | --------- | --------- |
| GLB 네트워크 요청                               | 4건         | **0건**   | **0건**   |
| 다운로드 완료 후에도 오버레이가 더 떠 있던 시간 | 1603ms      | 1673ms    | 1638ms    |

다운로드 시간은 절반이 됐는데 **꼬리는 ±40ms 안에서 일정하다.** 그 구간의 long task가 메인 스레드를 50~75% 점유한다.

그리고 오버레이 해제에는 **바닥이 있다.** `hasCompletedInitialBlockingLoad`는 컴포넌트 상태라 마운트마다 `false`이고, 해제 경로에 `INITIAL_BLOCKING_LOAD_READY_GRACE_MS = 600`이 있다. 프로덕션 빌드에서 오버레이는 일관되게 **~710ms**에 걸린다.

#### 큐브카메라 제거는 이득이 없었다 (측정 후 기각)

`<Preload all />`는 `useLayoutEffect`에서 `gl.compile()`과 **큐브카메라 6면 렌더**를 동기로 돈다. 이 씬은 `envMap`·`<Environment>`·큐브 텍스처를 하나도 안 쓰므로(라이트만 있다) 후자가 낭비로 보였다. 프로덕션 빌드에서 쿼리 플래그로 A/B 했다(각 3회):

|                       | `gl.compile()` | `CubeCamera.update()` | **오버레이 해제** | 최대 프레임 |
| --------------------- | -------------- | --------------------- | ----------------- | ----------- |
| compile + cube (현재) | 11.3ms         | **216.6ms**           | **710ms**         | 10ms        |
| compile only          | 9.9ms          | —                     | **708ms**         | 9.5ms       |

**큐브 패스는 216ms를 쓰지만 오버레이 해제 시각은 안 바뀐다(710 vs 708ms).** 위의 ~600ms 바닥 안에 통째로 숨어 있어서다. 잰크도 양쪽 다 0이었다(3초간 33ms 넘는 프레임 0개).

> **그래서 지금은 건드리지 않는다.** 제거해도 사용자가 체감할 이득이 없고, 큐브 패스는
> `gl.compile()`이 놓치는 셰이더 변형까지 워밍하는 안전망이라 잃을 것만 있다.
> **다만 저사양 기기에서는 600ms 바닥이 지배하지 않을 수 있어 216ms가 임계 경로로 올라올 수 있다.**
> 위의 600ms 바닥을 먼저 줄이게 되면 그때 다시 볼 것 — 그 시점엔 이게 다음 병목이다.

> **dev로 재면 틀린 결론이 나온다.** dev에서는 오버레이가 2100ms에 걸리고 큐브 패스가
> 290ms로 보여 "90%가 낭비"처럼 읽힌다. 프로덕션에서는 바닥이 달라 결론이 뒤집힌다.

### 🟠 N-2. SkinnedMesh 프러스텀 컬링으로 눈썹이 사라진다

카메라가 얼굴로 다가가면 `brows` mesh가 통째로 사라진다.

| scroll  | `brows`.visible | `brows`.inFrustum |
| ------- | --------------- | ----------------- |
| 380     | true            | true              |
| **450** | true            | **false**         |

`SkinnedMesh.boundingSphere`가 **bind pose 지오메트리**에서 계산되고 스킨·모프 변형을 반영하지 않아, 화면 안에 있는 mesh가 프러스텀 밖으로 판정된다. 눈썹이 먼저 걸린 건 바운딩 스피어가 제일 작기 때문이다(`brows` r=0.257, `eyebrow` r=0.310 — 후자는 생존).

→ `fix/character-skinned-mesh-culling`에서 SkinnedMesh 전체의 `frustumCulled`를 끈다. 캐릭터는 항상 화면 중앙이라 컬링으로 아낄 것이 없다.

## 4. 공통 규칙

- **`.claude/skills/gltf-pipeline`을 먼저 읽어라.** 이름 조회 제약, gltf-transform 금지 목록,
  KTX2 절차, `.vN` 캐시 버스팅이 전부 거기 있다. **이 문서와 충돌하면 스킬이 단일 출처다.**
- 에셋을 바꾸면 `preloadGLB.ts`의 `.vN`을 올린다. 안 올리면 immutable 캐시 때문에 옛 파일이 계속 서빙된다.
- 원본은 `assets-src/`에 백업되어 있다. 재변환 시 여기서 출발한다.
- 커밋 타입은 `pr-workflow` 스킬의 허용 표를 따른다. `⚡ perf:`는 **변형 선택자 없는 U+26A1**만 통과한다.
- PR 문서는 `docs/pr/`에 (`pr-workflow` 스킬), 아티클 초안은 워크트리 밖 `~/Documents/personal/chaen/docs/articles/`에 (`article-writing` 스킬). 둘 다 gitignore라 커밋되지 않는다.
- 검증: `pnpm run check-types` → `pnpm run lint` → `pnpm run test:vitest`. 3D 런타임을 바꿨으면 `pnpm run test:browser`까지.
- **성능·타이밍 주장은 headless로 재지 마라.** 소프트웨어 렌더링이라 프레임타임이 뭉개진다. GPU 활성 브라우저에서 잰다.
- 리뷰가 달리면 `follow-review` 스킬, 셀프 리뷰는 `self-review` 스킬.
